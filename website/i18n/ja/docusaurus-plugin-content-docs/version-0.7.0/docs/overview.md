# kroとは？

**kro**（Kube Resource Orchestrator）は、シンプルで分かりやすい設定を使用してカスタム**Kubernetes API**を定義できる、オープンソースのKubernetesネイティブプロジェクトです。kroを使用すると、Kubernetesオブジェクトのグループとそれらの間の論理演算を作成する新しいカスタムAPIを簡単に設定できます。kroは論理演算に[CEL（Common Expression Language）](https://github.com/google/cel-spec)を使用しています。これはKubernetes Webhooksで使用されているのと同じ言語です。CEL式を使用することで、あるオブジェクトから別のオブジェクトに値を渡したり、カスタムAPI定義に条件を組み込んだりできます。CEL式に基づいて、kroはオブジェクトが作成されるべき順序を自動的に計算します。API仕様のフィールドにデフォルト値を定義できるため、エンドユーザーはこれらのカスタムAPIを呼び出して、最小限の設定でグループ化されたリソースを作成できます。

# kroはどのように動作しますか？

### 開発者インターフェース

エンドユーザーが**カスタムAPI**を使用してYAML仕様をクラスターに適用すると、APIはクラスター内にリソースのセットを作成します。これらのリソースには、**ネイティブKubernetes**リソースとクラスターにインストールされている任意の**カスタムリソース定義（CRD）**の両方を含めることができます。これらのリソースの一部は、クラスター外に追加のリソースを作成する場合があります。

以下の図に示すように、開発者はカスタムAPIを呼び出し、**Deployment**、**Ingress**、**ServiceAccount**、**Prometheus Monitor**、**IAMロール**、**IAMポリシー**、**Amazon S3バケット**などのリソースを作成します。これにより、開発者は標準化された方法でアプリケーションを管理およびデプロイできます。

### ResourceGraphDefinition

クラスターに**kro**をインストールすると、**ResourceGraphDefinition（RGD）**と呼ばれるカスタムリソース定義（CRD）がインストールされます。**プラットフォーム**、**セキュリティ**、**コンプライアンス**チームが協力して、ResourceGraphDefinition CRDのカスタムリソースを定義することでカスタムAPIを作成できます。

示された例では、**プラットフォームチーム**が必要なリソースと追加のロジック、抽象化、およびセキュリティのベストプラクティスをカプセル化した「Application Stack」という任意の名前の**RGD**を作成しています。RGDがクラスターに適用されると、ApplicationStackという種類の新しいAPIが作成され、開発者が利用できるようになります。開発者は、基盤となるインフラストラクチャの複雑さを直接管理する必要がなくなります。カスタムAPIが必要なリソースのデプロイと設定を処理するためです。

### ResourceGraphDefinitionインスタンス

開発チームは、それぞれの特定の要件に合わせた**Application Stack**の複数のインスタンスを作成できます。示されているように、**開発チームA**と**開発チームB**はどちらも独自のApplication Stackをインスタンス化しています。基盤となるリソースは似ていますが、**開発チームA**はIngressオプションを使用してサービスを外部に公開することを選択し、**開発チームB**はサービスをクラスター内部に保持することを選択しています。この柔軟性により、各開発チームは特定の要件に基づいてアプリケーションスタックをカスタマイズできます。

# なぜkroなのか？

### あらゆるリソースグループを1つのユニットとして管理

**kro**を使用すると、**プラットフォームチーム**は開発チームがアプリケーションとその依存関係を1つのユニットとして迅速にデプロイおよび管理できるようにし、デプロイからメンテナンスまでのライフサイクル全体を処理できます。新しいAPIは開発者の既存のCDツールとシームレスに統合され、使い慣れたプロセスとインターフェースを維持することで採用を簡素化します。

### コラボレーション

**kro**を使用して、**Kubernetes**を統合プラットフォーム設定フレームワークに変換します。プラットフォーム、コンプライアンス、セキュリティチームが協力して、設定を標準化するAPIを開発し、開発チームがセキュアでコンプライアンスに準拠したプラクティスを採用しやすくします。このコラボレーションにより、組織の標準をAPIに直接組み込むことができ、開発者に複雑さを追加することなく、すべてのアプリケーションデプロイがセキュリティとコンプライアンスの要件に準拠することを保証します。

### 標準化

統一されたAPIを作成することで、すべての環境でベストプラクティスを定義および適用でき、すべてのアプリケーションが組織の要件を満たし、デプロイ環境全体で一貫性を達成できます。
